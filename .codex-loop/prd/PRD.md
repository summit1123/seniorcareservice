# 제품 요구사항 문서

## 작업 제목

안심반경 시니어 마일리지 심사위원용 React 데모와 1년 시뮬레이션 패키지

## 문제 정의

기존 마일리지 특약은 연간 주행거리와 차종으로 할인율을 판단한다. 이 구조는 명확하지만, 같은 저주행 시니어 안에서 생활권 안 안정형, 생활권 밖 안전형, 최근 위험변화형을 구분하지 못한다.

이번 작업의 목표는 기존 거리 기준 마일리지와 제안 통합 산식을 같은 1년 주행조건에서 비교하고, 심사위원이 한 화면에서 다음 질문에 답할 수 있게 만드는 것이다.

```text
같은 연간 주행거리라면 모두 같은 할인율을 받아야 하는가?
아니면 생활권 안정성과 위험변화를 함께 반영해야 하는가?
```

## 핵심 사용자

- 1차 사용자: 삼성화재 AI 공모전 심사위원
- 2차 사용자: 보험사 상품기획자, 데이터/AI 검토자
- 내부 사용자: 팀원, 발표자료 담당자

| 5,000km 이하 | 23% | 27% | 12% |
| 6,000km 이하 | 22% | 26% | 8% |
| 7,000km 이하 | 21% | 25% | 8% |
| 8,000km 이하 | 18% | 22% | 8% |
| 9,000km 이하 | 16% | 20% | 8% |
| 10,000km 이하 | 12% | 17% | 8% |
| 11,000km 이하 | 9% | 13% | 3% |

비교 원칙:

- 기존 방식은 연간 주행거리와 차종으로 최종 할인율 1개를 산출한다.
- 제안 방식도 최종 할인율은 연간 종합 점수로 1개만 산출한다.
- 월별 할인율, CAGR, 월복리 환산은 사용하지 않는다.
- 월별 데이터는 할인율이 아니라 생활권 변화와 위험변화의 판단 근거로 보여준다.

## 제안 산식

제안 산식은 기존 마일리지에 별도 항목을 붙이는 구조가 아니라, 기존 거리 중심 판단을 4개 지표 기반 통합 점수로 고도화하는 구조다.

## 산식 도출 논리

4개 지표는 임의로 붙인 항목이 아니라, 기존 마일리지 할인표를 기준선으로 둔 A/B 시뮬레이션에서 도출된 설명 축이어야 한다.

```text
1. 기존 마일리지 할인표를 30명 1년 주행 시나리오에 먼저 적용한다.
2. 같은 연간 주행거리 구간에서 서로 다른 운전 맥락이 섞이는지 확인한다.
3. 기존 방식이 구분하지 못한 차이를 Agent가 분석한다.
4. 그 차이를 설명하는 후보 지표를 제안한다.
5. 후보 지표를 조합해 제안 통합 산식 후보를 만들고 A/B 검증한다.
```

따라서 UI와 문서에서는 다음 흐름이 보여야 한다.

| 단계 | 질문 | 산출 |
|---|---|---|
| 기존 마일리지 적용 | 같은 거리 구간 고객이 모두 같은 할인 대상인가? | 기존 할인율, 기존 할인액 |
| 미구분 패턴 탐색 | 같은 할인 대상 안에 안정형과 위험변화형이 섞였는가? | 페르소나별 차이, 월별 주행 변화 |
| 설명 축 도출 | 무엇을 봐야 이 차이가 설명되는가? | 주행거리, 생활권 내 안정성, 생활권 밖 안전성, 생활권 밖 위험변화 |
| 산식 후보 탐색 | 어떤 가중치와 기준이 가장 납득 가능한가? | Senior Safe Mileage Score 후보 |
| A/B 검증 | 기존 대비 어떤 고객 판단이 달라졌는가? | 우대, 기본, 예방 케어, 할인액 차이 |

이 구조에서 4개 지표는 "정답을 미리 정한 점수"가 아니라, 기존 마일리지 기준선의 한계를 설명하기 위해 Agent 시뮬레이션과 정책 탐색에서 좁혀진 결과다.

```text
Senior Safe Mileage Score
= w1 * Mileage Score
+ w2 * In-Zone Safe Driving Score
+ w3 * Out-Zone Safe Driving Score
- w4 * Out-Zone Pattern Change Risk
```

4개 지표:

| 지표 | 의미 |
|---|---|
| Mileage Score | 연환산 주행거리가 낮을수록 높은 점수 |
| In-Zone Safe Driving Score | 생활권 안/버퍼 안에서 안정적으로 운전했는지 |
| Out-Zone Safe Driving Score | 생활권 밖에서도 과속, 급감속, 야간주행이 낮은지 |
| Out-Zone Pattern Change Risk | 최근 생활권 밖 주행과 위험행동이 평소보다 증가했는지 |

## 1년 시뮬레이션 구조

현재 90일 fixture는 1년 데모로 확장한다.

```text
6개 시니어 페르소나
* 각 5명
= 30명 가상 시니어 운전자

운전자별 사전 baseline 60일 주행 로그 생성
-> 운전자별 평가기간 12개월 주행 로그 생성
-> 매월 직전 60일 기준 생활권 계산
-> 해당 월 주행 평가
-> 12개월 점수를 연간 종합
-> 기존 마일리지 할인액과 제안 산식 할인액 비교
```

사전 baseline 60일은 생활권 기준을 만들기 위한 관찰 데이터다. 기존 마일리지 할인율, 제안 연간 점수, 할인액 비교에는 평가기간 12개월 주행거리만 사용한다. 즉 데모 데이터는 총 14개월에 가깝지만 상품 판단 기간은 1년으로 고정한다.

페르소나는 AI가 만든 시니어 주행 시나리오여야 하며, 단순 ID 목록이 아니어야 한다. 각 페르소나 프로필에는 다음 정보가 필요하다.

- 집, 병원, 마트, 자녀 집, 복지관 등 생활 목적지 anchor
- 월별 외출 빈도와 주행거리 성향
- 생활권 안/밖 이동 성향
- 야간주행, 과속, 급감속 등 위험행동 성향
- 특정 월에 발생하는 변화 이벤트
- 기존 마일리지가 놓칠 수 있는 이유

## 생활권 rolling 정책

생활권은 매월 직전 60일 주행 데이터를 기준으로 계산한다. 1월 평가도 cold-start가 되지 않도록 평가기간 시작 전 60일 baseline 주행을 별도로 생성한다.

| 항목 | 정책 |
|---|---|
| 생활권 계산 기준 | 매월 직전 60일 |
| 평가 대상 | 해당 월 30일 주행 |
| 사전 baseline | 평가기간 시작 전 60일, 생활권 학습 전용 |
| 연간 할인/점수 대상 | 평가기간 12개월 주행만 사용 |
| 모델 | DBSCAN + P90 버퍼 |
| P90 버퍼 | `max(500m, min(P90, 2km))` |
| 신규 목적지 | 즉시 안정 생활권으로 단정하지 않고 후보 생활권으로 표시 |
| 최종 판단 | 12개월 월별 평가를 연간 종합 |

데이터 누수 방지 규칙:

- 해당 월을 평가할 때, 같은 달 주행은 생활권 생성에 사용하지 않는다.
- 1월은 사전 baseline 60일만 생활권 생성에 사용한다.
- 2월 이후는 직전 60일 rolling window를 사용하며, 평가월 주행은 제외한다.
- 사전 baseline 주행거리는 기존 마일리지 연간 주행거리와 제안 연간 할인액 계산에서 제외한다.

새 목적지가 바로 생활권으로 흡수되면 위험변화가 사라질 수 있다. 따라서 UI와 산식은 다음 상태를 구분해야 한다.

- 기존 생활권
- 후보 생활권
- 생활권 밖 안정 주행
- 생활권 밖 위험변화

## React 데모 요구사항

기존 Streamlit/HTML 대시보드는 검증 로그와 데이터 목록이 먼저 보여 심사위원용 설득력이 약하다. 새 데모는 React 기반으로 다시 만든다.

React 단독 앱으로 끝내면 안 된다. 데이터 조회, 리포트 생성, LLM key 보호, Markdown streaming은 서버가 담당한다.

필수 서버 API:

| Endpoint | 역할 |
|---|---|
| `GET /api/personas` | 30명 페르소나 프로필 조회 |
| `GET /api/drivers/{driver_id}/annual-summary` | 선택 운전자 연간 주행/할인 비교 조회 |
| `GET /api/drivers/{driver_id}/monthly-snapshots` | 1월~12월 생활권/위험변화 snapshot 조회 |
| `GET /api/drivers/{driver_id}/zone-map?month=...` | 월별 생활권 지도용 좌표/클러스터 조회 |
| `POST /api/reports/stream` 또는 `GET /api/reports/stream` | 보험사 직원용 Markdown 리포트 chunk streaming |

Streaming 방식은 Server-Sent Events, fetch ReadableStream, chunked response 중 구현 난이도와 repo 환경에 맞는 방식을 선택한다. 중요한 것은 React가 가짜 타이핑 애니메이션을 만드는 것이 아니라 서버가 실제 리포트 chunk를 순차 전송하는 구조여야 한다는 점이다.

첫 화면은 다음 순서로 구성한다.

1. 상품명과 문제정의
2. 기존 마일리지 vs 제안 산식 핵심 비교
3. 30명 페르소나와 1년 시뮬레이션 요약
4. 선택 운전자 월별 생활권 변화 패널
5. 기존 할인액과 제안 할인액 차이
6. XAI 기반 보험사 직원용 월별/연간 리포트 생성

필수 화면:

| 화면 | 목적 |
|---|---|
| Executive Overview | 심사위원이 20초 안에 문제와 차별점을 이해 |
| Persona Lab | 30명 페르소나 프로필과 12개월 시나리오 확인 |
| Living Zone Timeline | 매월 직전 60일 기준 생활권과 해당 월 평가를 시각화 |
| Mileage A/B Comparison | 기존 할인표와 제안 산식의 연간 할인액/차액 비교 |
| XAI Report Panel | 보험사 직원용 reason code와 LLM 설명문 확인 |

## 시각화 품질 기준

React만 있으면 실패다. UI는 실제 심사용 제품 데모처럼 보여야 한다.

필수 시각화 패널:

- 기존 마일리지 할인표 기반 할인율 lookup 패널
- 30명 페르소나 분포와 유형별 요약
- 선택 운전자의 1월~12월 월별 주행/생활권/위험변화 타임라인
- DBSCAN/P90 생활권 지도 패널
- 기존 할인액 vs 제안 할인액 비교 패널
- XAI reason code와 직원용 리포트 패널

디자인 요구:

- `product-ops` 프리셋과 `impeccable-operator` 레퍼런스를 따른다.
- 보조 레퍼런스는 `analyst-workbench`다.
- 카드 남발, 장식 그래픽, 의미 없는 KPI 타일은 금지한다.
- 모든 시각화는 사용자의 판단을 도와야 한다.
- 텍스트는 잘리지 않아야 하고, 데스크톱/노트북 화면에서 가독성이 좋아야 한다.

## XAI/LLM 역할

XAI와 LLM은 보험료를 결정하지 않는다.

- 산식과 threshold는 deterministic scoring engine이 계산한다.
- XAI는 점수에 영향을 준 reason code를 생성한다.
- LLM은 privacy-filtered feature와 reason code를 보험사 직원용 설명문으로 변환한다.
- 원본 GPS, 실제 식별자, raw trip log는 LLM 요청에 포함하지 않는다.
- OpenAI API key가 없으면 리포트 생성을 중단하고 설정 오류를 표시한다. 보험사 직원용 리포트는 하드코딩 템플릿이 아니라 OpenAI LLM 스트리밍 응답으로만 생성한다.

리포트는 선택 운전자에 대해 보험사 직원이 바로 이해할 수 있는 Markdown 형식이어야 한다. 단순 판정 문구가 아니라 월별 운전 패턴과 연간 판단 근거를 함께 설명한다.

리포트 필수 섹션:

1. 운전자 페르소나 요약
   - 생활 목적지, 외출 빈도, 주요 운전 성향
2. 기존 마일리지 기준 결과
   - 연간 주행거리, 차종, 기존 할인율, 기존 할인액
3. 월별 운전 패턴 해석
   - 월별 주행거리, 생활권 내/밖 비율, 신규 목적지, 야간/과속/급감속 변화
4. 생활권 변화 해석
   - 사전 baseline 또는 직전 60일 기준 생활권, 후보 생활권, 생활권 밖 안정 주행, 위험변화 구간
5. 제안 산식 영향
   - 4개 지표가 최종 점수와 할인율/케어 판단에 미친 영향
6. 보험사 직원용 판단 가이드
   - 우대/기본/예방 케어 이유, 상담 또는 케어 안내 포인트
7. 주의사항
   - 실제 사고 예측이 아니라 시뮬레이션 기반 상품 기준 검증이라는 한계

React 화면에서는 이 리포트가 별도 프레임 안에 Markdown으로 streaming 표시되어야 한다. 생성 중에는 progress 상태와 현재 생성 중인 섹션명이 보여야 한다.

## 완료 기준

- 30명 가상 운전자에 대해 사전 baseline 60일과 평가기간 12개월 주행 로그, 페르소나 프로필이 생성된다.
- 1월부터 cold-start 없이 매월 직전 60일 기준 생활권 snapshot과 해당 월 평가 결과가 생성된다.
- 기존 삼성화재 마일리지 할인표와 제안 산식을 같은 연간 주행 데이터에 적용해 할인율, 할인액, 차액을 비교한다.
- React 데모가 실제로 실행되고, 핵심 화면이 심사위원용 흐름으로 보인다.
- XAI 리포트 생성 버튼이 선택 운전자의 월별/연간 reason code와 직원용 설명문을 보여준다.
- tests/build/screenshot 또는 이에 준하는 runtime evidence가 남는다.

## Non-goals

- 실제 보험료 산정 시스템이 아니다.
- 실제 사고율/손해율 개선을 입증한다고 주장하지 않는다.
- 고객별 실제 사고/청구 라벨 예측 모델을 만든다고 주장하지 않는다.
- 월별 할인율 변동 상품으로 설계하지 않는다.
- 기존 마일리지 할인에 단순 별도 혜택을 붙이는 구조로 표현하지 않는다.
