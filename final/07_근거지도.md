# 근거 지도 — 12개 질문의 논리 사슬과 근거 등급

> **왜 이 문서를 따로 만드나.** 마스터 답변안은 "답변"으로 잘 쓰여 있지만, 한 문단
> 안에 성격이 다른 것들(문헌·코드·합성 실측·설계값·미확인)이 섞여 흐르는 글로
> 되어 있어 **어느 고리가 단단하고 어느 고리가 빈지 눈으로 구분되지 않는다.**
> 이 문서는 각 항목을 **① 지적 → ② 논리 사슬 → ③ 고리별 근거와 등급**으로
> 분해한다. 답변 문장은 마스터 답변안에서 읽고, **어디를 찔리면 아픈지는 여기서**
> 확인한다.

## 근거 등급 기호

| 기호 | 뜻 | 심사에서 |
|---|---|---|
| ◎ | **코드·데이터 실물** — 우리가 돌려서 재현 확인 | 화면·코드로 즉시 증명 가능. 제일 강함 |
| ○ | **문헌 (원문 링크 확보)** | 출처를 대면 끝남 |
| △ | **문헌 (약칭만, 제목·링크 없음)** | "출처가 뭐냐"에 답 못 함. **인용 전 확인 필요** |
| ▽ | **설계값** — 근거가 없음을 우리가 인정 | 방어법은 "값이 아니라 순서·절차를 주장" |
| ✕ | **공백** — 아직 없음 | 물으면 "없습니다 + 로드맵"으로 답할 것 |

**핵심 원칙**: ◎와 ○로만 공격을 막고, ▽는 먼저 인정하고, △는 발표에서 쓰지 않는다.

## 1. 왜 고령자로만 한정했나

**논리 사슬**
```
우리 방식은 "개인의 평소"를 학습해 변화를 본다
  → 그러려면 평소가 안정적이어야 한다(기준선이 서야 한다)
  → 고령층은 생활 반경이 좁고 반복적이라 기준선이 가장 잘 선다
  → 젊은 층의 패턴 다양성은 우리 방식에선 신호가 아니라 노이즈
  → 확장에 필요한 건 알고리즘 교체가 아니라 학습 창 재조정
```

| 고리 | 근거 | 등급 |
|---|---|---|
| 고령층 이동 반경이 좁다 | LongROAD 자기규제(야간 회피 58.8%, 이웃 마을 밖 안 나감 22.6%) | ○ |
| 반복성이 기준선의 조건 | 우리 규칙(서로 다른 3일) 자체가 반복성 요구 — 코드 | ◎ |
| 젊은 층이 노이즈가 된다 | **직접 실험 없음** — 논증이지 실측 아님 | ✕ |
| 확장이 파라미터 문제 | 학습 창이 파라미터로 분리돼 있음(코드) | ◎ |

**약한 고리**: "젊은 층에선 안 된다"는 주장은 실험으로 뒷받침되지 않는다. 후속질문
("해보긴 했나")에는 **"안 해봤고, 방법론적 예측"**이라고 답할 것.

## 2. "대부분의 사고는 생활권 안에서 난다"

**논리 사슬**
```
동의한다 — 사고 건수는 생활권 안에 몰린다
  → 그건 위험의 지도가 아니라 노출의 지도다(주행 자체가 거기 집중)
  → 노출을 통제하면 오히려 익숙함이 보호적이다
  → 그래서 우리는 위치로 벌하지 않는다
  → 실제로 안(30)을 밖(20)보다 무겁게, 같은 잣대로 채점한다
```

| 고리 | 근거 | 등급 |
|---|---|---|
| 사고가 자택 근처에 몰림 | NMVCCS 70% 자택 5마일 이내 | ○ |
| 주행도 거기 집중(노출) | Burdett 2017 — 자택 11km 이내가 주행 절반 | ○ |
| 노출 통제 시 익숙함이 보호적 | Tefft 2021 — 같은 사고 현장 내 비교, 처음 도로 2.5배 | ○ |
| 위치 벌점 없음 | `location_penalty: 0.0` 전 반환 경로 하드코딩 | ◎ |
| 안 30 > 밖 20, 같은 잣대 | `DEFAULT_PRODUCT_RULES` + `_safety_score` 동일 함수 양쪽 적용 | ◎ |
| 밖 없으면 축 제외 | 180 중 58건 밖축 없이 판정, 그중 35건 우대 | ◎ |
| 안의 위험도 잡힘 | ② 유형 안 안전점수 15.8점, 우대 0/30 | ◎ |

**이 항목은 12개 중 가장 단단하다** — 전 고리가 ○ 또는 ◎.

## 3. 시뮬레이션 방법론과 'data' 용어

**논리 사슬**
```
'data'는 부정확한 표현이었다 → 합성 시나리오로 교체
  → 생성은 4단계(사람 정의 → LLM 프로필 → 결정론 엔진 → TAAS 유형분해)
  → 채점 엔진은 유형 라벨을 보지 못한다
  → 따라서 검증 대상은 예측력이 아니라 판정 로직의 일관성
```

| 고리 | 근거 | 등급 |
|---|---|---|
| 생성 체인 4단계 실재 | 코드·픽스처(`mobility_profiles.json` 등) | ◎ |
| 시드 고정 재현성 | `sha256(전역시드\|driver_id\|month)` | ◎ |
| 라벨 누출 없음 | `decision_feature_contract` 허용목록 8개에 라벨 없음 | ◎ |
| TAAS 가중치는 표시 전용 | 가중치 교체 후 180건 판정 diff 0 | ◎ |
| 파라미터 절대값의 근거 | **없음 — 방향성만 문헌** (문서가 인정) | ▽ |

**약한 고리**: 절대값(월 방문 13~42회, 위험률 3%/72%). 먼저 인정하고 "파일럿에서
실주행 경험분포로 대체"로 답할 것.

## 4. Safe Zone이 반경 기준뿐 — 지역 차등 필요

**논리 사슬**
```
차등은 이미 있다
  → ① 거점 인식 눈금: 지역 3단 eps (260/520/1,100m)
  → ② 생활권 원: 개인 실측 P90 (하한 500m·상한 2km)
  → ③ 지역 분류 기준: 운영 시 DEGURBA(UN 표준) 채택
```

| 고리 | 근거 | 등급 |
|---|---|---|
| eps 3단이 코드에 있음 | `ENVIRONMENTS`의 `dbscan_eps_m` | ◎ |
| 260이 문헌 대역의 중간 | Zheng 2009 200m / Montoliu 2013 250m(권장 200~300m) | ○ |
| 520·1,100은 ×2 축척 | 규칙일 뿐 — **검증된 바 없음** | ▽ |
| 원이 개인별로 갈림 | 광역 813m vs 도심·교외 500m (실측) | ◎ |
| 지역별 임계가 필요하다 | MDPI Appl.Sci. 15(22):12278 (⚠ 인구 격자 대상, 스케일 다름) | △ |
| DEGURBA 채택 | 결정만 있고 미구현 | ✕ |

**주의해야 할 두 가지**
1. **eps 3단은 최종 판정 반경에 영향이 없다** — 지역 eps와 전국 단일 260m로 각각
   돌려 비교한 결과 존 반경이 완전히 동일(도심 500/500, 교외 500/500, 광역
   813/813). 원은 `max(코어 500m, 개인 P90, 상한 2km)`라 eps가 그 층까지
   내려오지 않는다. **따라서 "3층 차등"을 말할 때 무게는 ①이 아니라 ②에 실어야
   한다.**
2. **순환 위험** — `ENVIRONMENTS`에 데이터 **생성** 파라미터(`visit_jitter_m`
   40/70/130)와 **분석** 파라미터(`dbscan_eps_m` 260/520/1,100)가 같이 들어 있다.
   "지역별로 다르게 뿌려 만든 데이터를 지역별로 다른 eps로 분석한 것 아니냐"는
   질문이 가능하다. 답: **맞다, 합성 검증은 순환을 피할 수 없다. 그래서 운영값은
   실데이터 k-거리로 재도출한다.**

## 5. 안전 운전자에게 매력 없는 상품 아닌가

**논리 사슬**
```
할증 경로가 코드에 존재하지 않는다(오버레이라서)
  → 단발 운행은 월 집계에서 임계의 1/7 수준
  → 이동·행동 동시 급변(AND)이라야 발동
  → 그 위에 사람 검토
```

| 고리 | 근거 | 등급 |
|---|---|---|
| 할증 경로 없음 | 180 시나리오 전건 `candidate_surcharge_rate_pct = 0` | ◎ |
| 월 집계 판정 | `_monthly_results` 월 단위 비율 계산 | ◎ |
| AND 게이트 | 이동 25%p **AND** 위험 20%p (`gate_logic: "AND"`) | ◎ |
| 단발이 안 걸림 | ③ 유형: 이동 임계 초과 191개월인데 케어 0건 | ◎ |
| 케어 시 할인 축소는 사실 | `care_discount_reduction_pct: 13.0` — 문서가 정직 고지 | ◎ |
| 케어 지속성 | 실측 케어 대상 전원 5~7개월 지속 | ◎ |

**이 항목도 단단하다.** 다만 "케어 월 1개만 있어도 연간 감액"은 사실이므로 먼저
인정하는 구조를 유지할 것.

## 6. 위치데이터 수집·보존의 법적 제약

**논리 사슬**
```
'6개월 삭제 의무' 조항은 없다 → 원칙은 목적 달성 시 즉시 파기
  → 우리가 위치를 쥐는 창은 학습 2개월 + 감지 직전 2개월 = 4개월
  → 그 뒤엔 파생값(존 중심·반경·비율)만으로 판정 성립
```

| 고리 | 근거 | 등급 |
|---|---|---|
| 법령 해석(즉시 파기 원칙) | 위치정보법 제23조 — **문서에 조문 인용은 있으나 링크 없음** | △ |
| 4개월 창 구조 | 기준선 2 + 직전 2개월 비교 = 코드 구조와 일치 | ◎ |
| 파생값만으로 판정 성립 | 존 레코드의 `privacy_filtered_features` 구조 실재 | ◎ |

**약한 고리**: 법령 해석이 우리 자체 해석이다. **법무 검토를 받은 적이 없다** —
심사에 법률 전문가가 있으면 위험. "법무 검토는 파일럿 전 필수 절차로 잡혀
있습니다"로 답할 것.

## 7. 베이스라인 2개월의 근거

**논리 사슬** (이게 실제 역산의 뼈대다 — 마스터 답변안 서술보다 이 순서가 명확)
```
1. 우리 규칙: 거점 인정 = 서로 다른 3일 이상 방문
2. 가장 뜸한 생활 거점의 빈도는? → 월 2회 수준
3. 관찰 창 1개월 → 그 거점 방문 2일 → 3일 미달 → 거점 탈락
4. 관찰 창 2개월 → 방문 4일 → 충족
5. ∴ 2개월 = 저빈도 생활 거점을 놓치지 않는 최소 창
   (보조 확인: 2개월이면 운전 자체가 26~43회라 표본도 충분)
```

| 고리 | 근거 | 등급 |
|---|---|---|
| 3일 임계 자체 | Isaacman 2011 — 60일 관찰의 5% = 3일, call-days 단위까지 동일 | ○ (PDF 링크 확보) |
| 3일의 오류율 계산 | 푸아송: 2일=오인 26%, 3일=8%, 4일=진짜 거점 절반 누락 | ◎ (재계산 가능) |
| "월 2회급" 빈도 앵커 | 건보 65세+ 월 3.75일 / 경로당 주 2.9회 / 복지관 주 1.5회 | △ (링크 없음) |
| 운전 빈도 26~43회 | 소비자원 2024 고령운전자 안전실태조사(n=300) — **링크 확보** | ○ |
| 관찰 창 선례 | UMTRI(*Traffic Inj Prev* 2018, PubMed 29584495) / DRIVES(PMC9535782) / Isaacman(PDF) / DHQ(PMC7317610) / Candrive(Marshall 2013, PubMed 23541299) — **5건 전부 링크 확보·응답 확인** | ○ |
| 우리 데이터 실측 | 369개 목적지 그룹 중 3일 미만 6개(1.6%), 진짜 거점 탈락 0 | ◎ |
| 업계 UBI 3~6개월 | 원출처 미확보 | ✕ **발표 인용 금지** |
| KTDB 2013 트립당 14.0km | 원문 링크 미확보 | ✕ |

**2026-07-29 보강 완료.** 종전에 약칭만 있던 6건 중 **5건의 정식 서지와 링크를
확보**해 근거 노트 2-2에 반영했다(HTML 상세판에는 이미 있었고 마크다운에만 누락돼
있었음). 남은 공백은 **업계 UBI 관행(3~6개월)과 KTDB** 둘이며, 둘 다 발표에서
쓰지 않는다 — "연구 기준선(2주~1개월)보다 보수적"까지만 말하고 업계 비교는 생략.

또한 **2-1의 역산 논리를 4단계로 재서술**했다(3일 임계 → 뜸한 거점 월 2회 →
1개월이면 2일로 미달 → 2개월이면 4일로 충족). 기존 서술은 이 고리가 생략돼
"운전 26~43회"만 남아 읽히지 않았다.

## 8. 페르소나가 '예쁘게' 나오는 구조 아닌가

**논리 사슬**
```
맞다 — 파라미터 기반 합성이고 결과는 설계의 산물이다
  → 그러나 페르소나는 결과 생성기가 아니라 테스트 집합이다
  → 각 유형은 사전 선언된 가설과 기대 결과를 갖는다
  → 채점 엔진은 유형 라벨을 보지 못한다
  → 실패해야 할 케이스(③)가 포함돼 있고 실제로 실패했다
  → ∴ 검증되는 것은 예측력이 아니라 로직 일관성
```

| 고리 | 근거 | 등급 |
|---|---|---|
| 라벨 누출 없음 | `decision_feature_contract` 허용목록 8개 | ◎ |
| ③ 오탐 대조군 작동 | 이동 임계 초과 191개월 / 최대 73.9%p / **케어 0건** (엔진 재실행 재현) | ◎ |
| ④ 케어 발동 | 30/30, 규칙 위반 0 | ◎ |
| ② 만성≠변화 구분 | 안 안전점수 15.8, 우대 0/30, 케어 0/30 | ◎ |
| 유형 실재(①②④) | LongROAD·CMT·Candrive·DRIVES·Bayat | ○ |
| 유형 실재(③⑤⑥) | Hirsch 2014 / Ji 2023 / KIRI — **링크 미확보** | △ |
| 10명 균등 배분 | 인구 비율 아님(테스트 설계) — 논증 | ▽ |

**191개월/케어 0건이 이 항목의 최강 카드**다. "이동만 191개월 튀었는데 한 번도
케어가 안 났다"는 AND 게이트가 실제로 작동한다는 반증 가능한 증거다.

## 9. '루프' 용어

**논리 사슬**
```
지적 수용 → 단어 폐기
  → 실제 구조는 생성 → 검토 → 승인 파이프라인
  → 재시도는 JSON 구조 계약 위반 시에만, 최대 3회
  → 판정 결과는 재시도 판단의 입력이 아니다
  → ∴ "원하는 결과가 나올 때까지 반복"이 구조적으로 불가능
```

| 고리 | 근거 | 등급 |
|---|---|---|
| 재시도 조건이 구조 계약뿐 | 코드 | ◎ |
| 판정이 재시도 입력이 아님 | 코드 | ◎ |
| 산출물 1회 생성 후 고정 커밋 | `mobility_profiles.json` 커밋 실재 | ◎ |

**전부 ◎인데 덱만 안 고쳐졌다.** 발표 자료에 '루프'가 남아 있으면 이 답변이
무의미해지므로 최우선 확인.

## 10. DBSCAN이 도농 밀도차에서 안전한가

**논리 사슬**
```
그 한계는 DBSCAN 원논문이 스스로 자인했다(p.229)
  → ① 전역 eps 폐기 — 지역별 260/520/1,100m
  → ② 밀도 단독으로 거점 인정 안 함 — '서로 다른 3일' AND
  → ③ 원 크기를 군집 모양에서 분리 — 코어 500m + 개인 P90
  → 실측: 과병합 0%, 반복거점 누락 1.6~3.1%
```

| 고리 | 근거 | 등급 |
|---|---|---|
| 원논문 자인 | Ester 1996 KDD p.229 원문 인용 + PDF 링크 | ○ (확보) |
| 3일 AND 규칙 | `dbscan_distinct_days` 코드 | ◎ |
| 원이 군집 모양과 무관 | 코드 + 실측(eps 바꿔도 존 반경 동일) | ◎ |
| 실험실 채점표 | 과병합 0%, 누락 1.6/2.4/3.1%, 커버리지 90.9/90.5/85.9% | ◎ |
| HDBSCAN 비교 | 9지표 실측 — 판정 성능 동급, 거점 수·노이즈만 차이 | ◎ |
| eps 값 자체 | 문헌 대역 기반 설계값 | ▽ |
| 해법 계보(VDBSCAN·OPTICS 등) | 서지는 정확, **링크는 일부만** | ○/△ |

**주의**: 2026-07-29에 "HDBSCAN 커버리지 90%→71.9%" 서술을 **철회**했다. 71.9%는
대표 사례 1명의 값인데 같은 사람의 DBSCAN도 71.9%였다(인과 오귀속). 마스터
답변안 10번은 이미 정정된 버전이므로 그대로 쓰면 되지만, **옛 슬라이드에 그
수치가 있으면 반드시 제거**할 것.

## 11. 가중치 30/30/20/20의 근거

**논리 사슬**
```
이건 요율이 아니라 할인 자격 점수의 배분이다
  → 네 축은 순보험료 분해에 1:1 대응한다
  → 안 30 > 밖 20은 신뢰도(credibility) 원리 — 표본이 두꺼운 쪽에 무게
  → 우리가 주장하는 건 값이 아니라 순서다
  → 값 자체는 회랑(35:15 ↔ 25:25)의 중간인 설계값
```

| 고리 | 근거 | 등급 |
|---|---|---|
| 오버레이 구조 | 할증 경로 0, 하한 = 기준 요율 (코드) | ◎ |
| 축이 순보험료 분해에 대응 | 논증 (계리 원리) | ○ 수준의 원리이나 인용 없음 → △ |
| 신뢰도 원리 | 계리학 표준 개념 — **교과서 인용 없음** | △ |
| 값 30/30/20/20 | **설계값** — 문서가 인정 | ▽ |
| ±10 강건성 실측 | **미실시** — 백로그(반나절) | ✕ |

**가장 약한 항목.** 심사위원이 "왜 30이냐"를 파고들면 **"값이 아니라 순서를
주장한다 + 강건성 실측은 아직 안 했다"**로 정직하게 접는 게 유일한 방어다.
발표 전에 ±10 강건성을 돌려두면 ✕가 ◎로 바뀐다 — **투자 대비 효과가 가장 큰
한 건**.
