## 1. 전략·기획 총론

### 1.1 문제정의 (재서술 확정본)
- (구) 고령 → 반응능력 저하 → 생활권 밖 사고 위험  ← 인과 공격에 노출, 폐기
- (신) **고령 운전자의 사고 위험 신호는 "익숙한 생활 패턴 대비 이동·행동의 동시 급변"이다.**
  급변은 신체·인지 변화의 조기 신호로 보고되며, 사고 "원인" 주장이 아니라 "사람이
  점검할 때"라는 **개입 트리거**로만 쓴다. 위치(밖·멀리) 자체는 판정에 중립.

### 1.2 상품 구조 (2축)
- **우대 축(연간·보험료)**: 4지표 가중합(주행 30·권내안전 30·권외안전 20·패턴 20) ≥ 75점을
  12개월 중 9개월 충족 시 우대(보너스 최대 7%p). 데이터 미달은 '보류'(불이익 없음).
- **케어 축(월·개입)**: 2단계 — **감지** = 직전 2개월 평균 대비 이동변화 ≥25%p AND
  위험행동변화 ≥20%p 동시 초과 / **유지** = 원래 생활권 복귀 전까지. 발동해도
  벌점·할증 없음. 그 달 보너스만 정지(케어 감액 13%p 후보) + 사람 검토 + 예방 지원.
- 두 축은 독립: "연간 우대 + 케어 월 존재"가 공존 가능(허순덕 케이스).

### 1.3 원칙 선언 (문서·화면에 실재)
- 위치 중립: `outer_zone_policy: "context_only_no_location_penalty"` (engine.py DEFAULT_PRODUCT_RULES)
- 클레임 경계: 대시보드 `claim_boundary` — 합성·로직 검증용, 실측 아님 명시
- TAAS 역할 선언(TEAM_STATUS.md): "개인 사고 예측 라벨 아님 — ①필요성 근거 ②위험행동 유형 가중치는 TAAS 표에서 직접 계산"
- 원시 GPS 비노출: allowlist sanitizer(`gaip_server_policy.ts`) — 좌표는 UI로 못 나감,
  지도는 자택 기준 상대변위(10m 반올림)만

## 2. 시스템 전모 — 데이터 생성 3층 파이프라인

```
[1층: 사람 손 — 유형·파라미터 설계]          personas.py
   6개 아키타입 × 성향 파라미터(부록 A)
   위험행동 유형 구성 설계 ← TAAS 통계 / 유형 분해 가중치는 엔진이
   TAAS 가중치표에서 직접 계산(taas_risk_weights.py, 부록 H)
        │
[2층: LLM — 생활권 프로필 생성]              mobility_agent.py (프롬프트 원문 = 부록 E)
   사람별 존 구성(장소·방향·비중·변화 시점)
   구조 계약은 코드가 검증·재시도(validate_profile)
   결과는 data/fixtures/mobility_profiles.json에 캐시(재현성)
        │
[3층: 결정론 엔진 — 이벤트 생성·채점]         engine.py
   시드 = sha256(seed|driver_id|month) → 같은 입력 = 같은 데이터
   유형을 모른 채 DBSCAN 군집 → 존 판정 → 월별 채점 → 2단계 케어(부록 D)
        │
[검증] pytest 254(계약) · JS 22(UI-엔진 일치) · 전수 감사 스크립트
```

핵심 문장: **"LLM은 삶을 쓰고, 엔진은 유형을 모른 채 채점한다."** (블라인드 채점 구조 —
설계자가 판정 결과를 직접 심는 게 아니라, 성향→행동→판정이 파이프라인을 거쳐 발현)

### Q1. [상품파트] 인과 흐름이 부자연스럽다 — 상관관계 아닌가

**의도**: 인과 주장 방어 가능성 시험. 익스포저 교란(고속도로·장거리) 반박 준비됐나.

**답변 스크립트**:
"정확한 지적이고, 저희 판정 로직이 이미 그 지적대로 설계돼 있습니다. 위치는 평가에
중립이라 생활권 밖 이동 자체로는 아무 일도 일어나지 않습니다. 저희 신호는 '그 분의
평소 대비 이동과 위험행동이 같은 달에 함께 급변했는가'이고, 이것도 사고의 원인
주장이 아니라 사람이 점검해야 할 시점이라는 개입 트리거로만 씁니다. 그래서 지적하신
교란 요인들 — 고속도로 비중, 운행거리 증가 — 은 판정에 진입하지 않습니다. 문제정의
서술은 '변화 감지' 프레임으로 수정하겠습니다."

**근거 포인터**: engine.py `outer_zone_policy`, 이동변화·안전유지형 30건 전원 우대(오탐 0),
안전점수는 100km당 비율(부록 D).

**예상 재반박**: "급변이 위험하다는 근거는?" → "저희도 급변=사고라고 단정하지 않습니다.
급변은 확인이 필요한 신호이고, 그래서 자동 감액이 아니라 사람 검토+검진 연계입니다.
개입해서 아무 일 없으면 다음 달 복귀 시 자동 해제됩니다."

### Q2·Q8. 왜 고령자만인가 / 전연령 확장은

**답변 스크립트**:
"30~50의 페르소나 다양성이 위험 구분에 유의미하다는 데 동의합니다. 다만 저희 방식은
개인의 익숙한 생활권을 기준선으로 학습하는 구조라, 기준선은 패턴이 안정적일 때만
성립합니다. 30~50의 출퇴근·레저·라이딩 다양성은 저희에겐 신호가 아니라 노이즈입니다.
시니어는 이 방법론이 성립하는 유일한 출발점이고, 동시에 저주행·고심도로 기존 마일리지
체계에서 과소평가된 protection gap 세그먼트이며, 검진·상담 개입의 효용이 가장 큰
연령대입니다. 확장은 시니어에서 검증한 '변화 감지 엔진'을 다중 기준선(출퇴근 기준선,
주말 기준선)으로 일반화하는 3단계 로드맵으로 제시하겠습니다."

### Q4. [일반상품] 생성 방식 — 전자(경험분포)인가 후자(파라미터)인가

**의도**: 순환논증 검증("퍼포먼스가 시나리오 설계의 결과").

**⚠ 1차 자료 정합 브리지 (답변 첫 문장에서 우리가 먼저 교정)**: 심사위원이 본
1차 발표자료에는 "**실제 드라이빙 로그를 바탕으로 6개 운전자 범주 및 30명**"이라
기재돼 있다 — 현재 실물(6유형 × 60명 × 3환경 = 180 시나리오, 파라미터+LLM 생성)과
수·생성방식 서술이 모두 다르고, '실제 로그 기반'은 부정확한 표현이었다. 전자/후자
질문 자체가 이 문구를 찌른 것이므로, 심사위원이 불일치를 먼저 지적하기 전에 이렇게
연다: "1차 자료의 '실제 드라이빙 로그 기반 30명' 표현은 부정확했습니다. 이후 데이터
파이프라인을 전면 재설계해 현재는 6개 유형 × 60명 × 3개 지역환경 = 180개 시나리오
이고, 생성 방식은 질문 주신 분류로 후자입니다."

**답변 스크립트**:
"후자입니다 — 사전 정의한 6개 유형에 파라미터를 설정해 생성했습니다. 그리고 판정
결과가 시나리오 설계의 결과라는 지적도 맞습니다. **그게 이 단계의 목적입니다.**
저희가 합성으로 검증하는 건 예측력이 아니라 상품 로직의 일관성 — 케어가 나야 할
설계에서 나고, **나면 안 되는 설계(이동만 커지는 이사형 30건)에서 안 나는지** —
이고, 계약 테스트 254건으로 상시 검증합니다. 예측력 주장은 하지 않으며 화면에 그
경계가 선언돼 있습니다. 파라미터는 무근거가 아닙니다: 위험운전 유형 분해 가중치는
도로교통공단 TAAS 2010~2024 원천 통계에서 산출한 가중치표를 **엔진이 직접 읽어
계산합니다** — 원천 CSV → 산출 코드 → 엔진 가중치 사슬이 저장소에 실물로 있어
열어서 따라가실 수 있습니다. 발생확률·주행거리의 절대 수치는 설계값으로 이 부분의
통계 앵커를 보완 중입니다. 예측력 검증은 파일럿 몫입니다."

**구조 강조(블라인드 채점)**: "유형이 판정을 직접 정하지 않습니다. 유형→성향
파라미터→LLM 생활권→결정론 이벤트→**유형을 모르는 엔진의 군집·채점** 순서라,
'설계 의도가 파이프라인을 통과해 발현되는가' 자체가 검증 대상입니다."

**예상 재반박**: "그 로직 검증도 결국 만든 사람이 채점하는 것" → "그래서 검증을
반증 가능하게 만들었습니다: 임계·가중치가 전부 선언돼 있고, 요율 샌드박스에서
심사위원이 직접 임계를 바꾸면 판정이 재계산됩니다. 숨은 튜닝이 없습니다."

### Q5. [일반상품] Safe Zone 지역 차등화 제안 — ★최강 카드

**맥락**: 심사위원이 본 1차 자료는 "오직 반경거리 기준"이었고, 제안문이 답 문구까지
줬다 — "도시형, 교외형, 농촌형 같이 단순한 지역유형을 구분하고 차등화 **하였다고
발표 가능할 것**". 우리는 '발표 가능한 문구'가 아니라 정확히 그 3분류의 **실물
구현+라이브 시연**으로 답한다(제안 어휘와 구현이 1:1). 1차 자료 이후 이미 구현
완료된 상태임을 자연스럽게 드러낼 것.

**답변 스크립트**:
"제안 주신 구조가 정확히 현재 구현입니다. 군집 기준거리를 도심 260m·교외 520m·광역
1,100m로 차등 적용하고, 같은 사람을 세 환경에 두는 통제 비교를 실측 화면('알고리즘
실험실')으로 제공합니다 — 동일인의 생활권 반경이 485m/800m/1,619m로 환경에 맞게
잡히는 걸 보실 수 있습니다. 여기에 판정을 거리 절대값이 아니라 비율로 설계해서 '도심
